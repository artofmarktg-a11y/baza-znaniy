# База знаний

Next.js-приложение с PostgreSQL и Prisma для обучения сотрудников.

## Локальный запуск

1. Создайте `.env` по образцу `.env.example` и задайте уникальный пароль PostgreSQL.
2. Запустите базу: `docker compose up -d`.
3. Установите зависимости: `npm ci`.
4. Примените миграции: `npm run db:migrate:dev`.
5. Только для новой пустой локальной базы заполните материалы: в PowerShell выполните `$env:CONFIRM_DATABASE_SEED='first-run'; npm run db:seed`, затем закройте терминал или удалите эту переменную.
6. Один раз создайте локального администратора, задав в `.env` логин и новый сложный пароль: `npm run db:bootstrap-admin`.
7. Запустите сайт: `npm run dev`.

## Production: PostgreSQL и Prisma

`prisma migrate dev` предназначена только для разработки: она создаёт и изменяет миграции. На боевой БД её не используют.

### Первый запуск новой боевой БД

1. Создайте PostgreSQL на платформе. `DATABASE_URL` должна быть задана платформой для контейнера приложения и, если сборка обращается к данным, для сборки.
2. Установите зависимости и соберите приложение: `npm ci` и `npm run build`.
3. В отдельном release-этапе, до запуска приложения, выполните `npm run db:deploy`. Команда применяет только уже закоммиченные миграции из `prisma/migrations` и не создаёт новых.
4. Один раз заполните новую базу материалами. Временно передайте переменную `CONFIRM_DATABASE_SEED=first-run` только команде `npm run db:seed`. После успешного выполнения удалите эту переменную из панели платформы.
5. Один раз создайте администратора: временно задайте `BOOTSTRAP_ADMIN_USERNAME` и новый пароль длиной не менее 16 символов с прописными, строчными буквами, цифрами и специальным символом; выполните `npm run db:bootstrap-admin`. Сразу удалите `BOOTSTRAP_ADMIN_PASSWORD` из переменных окружения.
6. Запустите приложение: `npm run start`.

Не добавляйте `db:seed` или `db:bootstrap-admin` в автоматический пайплайн деплоя. Seed намеренно требует одноразового подтверждения: он обновляет учебные данные и исходную матрицу ролей, поэтому повторный запуск может отменить настройки доступа, сделанные в интерфейсе.

### Каждый следующий деплой

1. Локально создайте миграцию: `npm run db:migrate:dev -- --name краткое-описание`.
2. Проверьте код и добавьте папку миграции в репозиторий.
3. На сервере выполните только `npm run db:deploy` перед стартом новой версии.
4. Не выполняйте `db:seed` и `db:bootstrap-admin`.

Проверить состояние миграций можно командой `npm run db:status`.

## Команды Prisma

| Команда | Назначение |
| --- | --- |
| `npm run db:migrate:dev` | Только локальная разработка: создание и применение миграций. |
| `npm run db:deploy` | Только production/release: применение готовых миграций. |
| `npm run db:status` | Проверка состояния миграций. |
| `npm run db:seed` | Только первое заполнение пустой БД и только с временной переменной подтверждения. |
| `npm run db:bootstrap-admin` | Одноразовое создание первого администратора. |
